# Tempo C++ Client API

Drop-in C++ client library for the Tempo simulation server. Generated by
`gen_cpp_api.py` at Tempo build time when `TEMPO_GEN_CPP_API=1`.

## What's in this folder

```
TempoConfig.cmake             # find_package(Tempo CONFIG): targets tempo::tempo, tempo::reflected
include/
  tempo.h                     # umbrella header for the RPC client
  tempo/                      # context.h, error.h, result.h, streaming.h, one header per service,
                              # and unreal.h, world.h, conversion.h: the reflected API's runtime
    reflected/                # the reflected API, when it was built (at package time)
  proto/
    <Package>/<File>.pb.h     # protoc-generated message types
lib/
  <Platform>/libtempo.a                   # wrappers, runtime and protoc outputs (tempo.lib on Windows)
  <Platform>/libtempo_reflected.a         # the reflected API, when it was built (tempo_reflected.lib)
third_party/grpc/include/     # in Packaged/API/Cpp only: the vendored gRPC headers
```

In `Packaged/API/Cpp`, `lib/<Platform>/` also holds the shared `tempogrpc` library. In the build
tree (`TempoCore/Content/Cpp/API`), `TempoConfig.cmake` finds both beside it, in the vendored gRPC.

## Integration

```cmake
find_package(Tempo CONFIG REQUIRED PATHS <this folder>)
target_link_libraries(my_client PRIVATE tempo::reflected)   # or tempo::tempo for RPCs alone
```

The targets carry the include paths, the defines this library was built with, `-fno-rtti` and C++20,
and link the shared `tempogrpc` library, which carries gRPC, protobuf, abseil, OpenSSL and zlib. Link
nothing else from gRPC: the static archives beside the shared library would duplicate its global
state. On Windows, copy `tempogrpc.dll` next to the executable.

## Quick start

```cpp
#include <tempo.h>

int main() {
    tempo::set_server("localhost", 10001);
    // Or, for a server on this machine listening on a Unix domain socket (Linux/macOS):
    // tempo::set_socket("sim-a.sock");

    auto result = tempo::tempo_core::get_current_level_name();
    if (!result) {
        std::fprintf(stderr, "request failed: %s\n", result.error().what().c_str());
        return 1;
    }
    std::printf("current level: %s\n", result.value().level().c_str());
    return 0;
}
```

## Arguments

Each RPC's wrapper takes one argument, a struct of its request's fields named for the request
(`SetPropertyRequest` -> `SetPropertyArgs`), in the service's namespace. Name the fields you set with
designated initializers, in the order the struct declares them; every field you leave out is sent
unset, so a field added to a request later breaks no call.

```cpp
TempoWorld::Value value;
value.set_float_value(1200.0);
auto set = tempo::tempo_world::set_property({.actor = "Truck", .property = "MaxSpeed", .value = value});
```

A string or a number left out is its zero. A message, a oneof member or an `optional` field is a
`std::optional`, left unset unless given. An RPC whose request is `TempoCore.Empty` takes no
argument. A wrapper for a deprecated RPC is `[[deprecated]]`, and a deprecated request field is not
offered at all: its replacement is.

The property and function RPCs (`get_property`, `set_property`, `call_function`, `run_batch`, ...)
speak Unreal's own units -- centimeters, degrees, left-handed -- as a `TempoWorld::Value` always is.
Every other RPC speaks meters, radians and right-handed. `tempo/conversion.h` converts between them.

## Streaming RPCs

```cpp
auto stream_result = tempo::tempo_sensors::stream_color_images({.owner = "Vehicle", .sensor = "Cam0"});
if (!stream_result) { /* handle error */ }
auto stream = std::move(stream_result).value();

TempoSensors::ColorImage frame;
while (stream.read(&frame)) {
    // process frame
}
auto status = stream.finish();
```

## ABI considerations

`libtempo` was compiled against the gRPC that ships in the Tempo plugin, as a consumer of its shared
library (`PROTOBUF_USE_DLLS`, `ABSL_CONSUME_DLL`). The protobuf-generated stubs inside the archive are
tightly coupled to that gRPC's ABI, so link that library and no other.

## Multi-platform

The archives are built for the host that built them, in `lib/<Platform>/` (Mac, Win64 or Linux),
and a package carries its host's. Nothing here is committed: build or package on each platform.

## Build prerequisites for regeneration

If you're regenerating with `TEMPO_GEN_CPP_API=1`:
- `cmake` 3.20 or later on `PATH`.
- A C++20-capable host compiler (clang 14+, gcc 11+, or MSVC 19.30+). On Linux, clang with libc++
  (`clang`, `libc++-dev`, `libc++abi-dev`), the standard library the shared `tempogrpc` library is
  built with; consumers there compile against libc++ too, which `TempoConfig.cmake` arranges.
- The Tempo Python venv (set up automatically by Tempo's prebuild).

Consumers who link against `libtempo` must also build their code with C++20:
the vendored gRPC's absl headers depend on `std::weak_ordering` and other
C++20 spaceship-operator types.
