# Migrating to Tempo v0.4.0

v0.4.0 adds the [reflected API](../clients/reflected-api.md), and with it a cleanup of the
TempoWorld property API it is built on. Nothing about plugins, modules, Blueprints or config
changes; all of the work is in client code.

## What changed at a glance

| Change | Affects | Breaks |
|---|---|---|
| Rust and C++ wrappers take one request argument | Rust, C++ clients | compile |
| Property and function values are always Unreal-native | all clients using `set_property`, `get_property`, `call_function` or `call()` | :material-alert: **silently, at runtime**, for rotators and quaternions |
| `Value.transform_value` removed; transforms travel as `native_transform_value` | all clients | compile (Rust, C++), at runtime (Python) |
| `TempoCore.Transform` carries a `scale`; the separate `scale` fields are deprecated | all clients | nothing yet; deprecation warnings |
| The 38 typed `set_*_property` RPCs and `set_properties` are deprecated | all clients | nothing yet; deprecation warnings |
| `Quat` is `double`; `Color.a` is optional | Rust, C++ clients | compile, where the types are spelled out |

The second row is the dangerous one: a rotator handed to `set_property` in radians still compiles
and runs, and turns the property by a fraction of a degree.

## What you need to do

### 1. Pass Rust and C++ wrappers their request

Every generated Rust and C++ function used to take one positional parameter per request field, so
adding a field to a request broke every call. Each now takes a single argument, naming only the
fields you set; a field added in a later release takes its default instead.

=== "Rust"

    ```rust
    // Before
    let state = tempo_world::get_current_actor_state("MyActor".into(), false)?;

    // After: the request message, re-exported by its module
    let state = tempo_world::get_current_actor_state(tempo_world::ActorStateRequest {
        actor: "MyActor".into(),
        ..Default::default()
    })?;
    ```

=== "C++"

    ```cpp
    // Before
    auto state = tempo::tempo_world::get_current_actor_state("MyActor", false);

    // After: a generated aggregate, set with designated initializers in declaration order
    auto state = tempo::tempo_world::get_current_actor_state({.actor = "MyActor"});
    ```

An RPC whose request is `TempoCore.Empty` takes no argument in either language, as before. Python
is unchanged: its wrappers already took keyword arguments.

The `call()` builder keeps its shape in all three languages.

### 2. Give property and function values in Unreal's units

`set_property`, `get_property`, `get_properties`, `stream_property`, `call_function`, `run_batch`
and the `call()` builder now take and report every value exactly as Unreal stores it —
centimeters, degrees, left-handed — and convert nothing. Before v0.4.0 they converted rotators,
quaternions and transforms from radians and right-handed while leaving everything else raw.

| Value | Before | Now |
|---|---|---|
| `rotator_value`, `rotator_arg` | roll/pitch/yaw in radians, right-handed | Unreal's roll/pitch/yaw in **degrees** |
| `quat_value`, `quat_arg` | right-handed | Unreal's own left-handed `FQuat` |
| a transform | `transform_value`: meters, radians, right-handed, no scale | `native_transform_value`: translation in cm, rotation as a quaternion, scale |
| an `FLinearColor` property, read | `color_value`, 8-bit | `linear_color_value` |
| scalars, vectors and everything else | raw | raw, unchanged |

Find every `rotator_value`, `quat_value`, `rotator_arg` and `quat_arg` in your code: nothing fails
to build or raises there. A transform fails loudly instead, since `transform_value` and
`transform_arg` are gone.

To keep working in the API's units, convert at the call site. `tempo_sim.conversion` (Python),
`tempo_sim::conversion` (Rust) and `tempo/conversion.h` (C++) convert between Unreal's value types
and the TempoCore messages with the server's own rules. See
[Units and coordinates](../concepts/conventions.md#the-exception-set_property).

### 3. Move off the deprecated typed setters

The 38 typed setters — `set_bool_property`, `set_float_property`, `set_vector_property` and the
rest, with their `_array` and `_set` forms — and `set_properties`, with the `batch()` builder over
it, still work exactly as before but are deprecated and will be removed in a later release.
Python warns with a `DeprecationWarning` on every call; Rust and C++ mark them `#[deprecated]` and
`[[deprecated]]`.

| Deprecated | Replacement |
|---|---|
| `set_<type>_property(actor, component, property, value)` | `set_property(actor, component, property, value=Value(<type>_value=...))` |
| `set_<type>_array_property`, `set_<type>_set_property` | `set_property` with the `<type>_array_value` or `<type>_set_value` variant |
| `set_properties`, `batch()` | `run_batch`, whose `set` ops take a `SetPropertyRequest` |

```python
# Before
tw.set_float_property(actor="BP_SensorRig", component="TempoCamera", property="FOVAngle", value=60.0)

# After
from tempo_sim.TempoWorld.WorldControl_pb2 import Value
tw.set_property(actor="BP_SensorRig", component="TempoCamera", property="FOVAngle",
                value=Value(float_value=60.0))
```

!!! warning "Rotators, quaternions and transforms change units on the way"

    The deprecated `set_rotator_property`, `set_quat_property` and `set_transform_property` keep
    converting from radians and right-handed. `set_property` does not (see step 2), so convert the
    value when you move one of those calls over.

### 4. Put scale in the transform

`TempoCore.Transform` gained a `scale`. Where you give a transform, leaving it unset means
(1, 1, 1); every transform Tempo reports has it set.

- `spawn_actor` applies the transform's scale. It never composes through `relative_to_actor`.
- `set_actor_transform` and `set_component_transform` honor `transform.scale` as they honored their
  separate `scale` field, which is deprecated: it still works when `transform.scale` is unset, and
  setting both is an `INVALID_ARGUMENT` error.
- `get_actor_transform` and `get_component_transform` report the scale in `transform.scale`. Their
  separate `scale` field is deprecated and holds the same value.

```python
# Before
tw.set_actor_transform(actor="MyActor", transform=Geometry.Transform(),
                       scale=Geometry.Vector(x=2.0, y=2.0, z=2.0))

# After
tw.set_actor_transform(actor="MyActor",
                       transform=Geometry.Transform(scale=Geometry.Vector(x=2.0, y=2.0, z=2.0)))
```

### 5. Update spelled-out types

- `Quat`'s components are `double`: `f64` in Rust, `double` in C++.
- `Color.a` is a proto3 `optional`: `Option<i32>` in Rust, `has_a()` in C++. An unset alpha in a
  write means opaque, 255, as before.
- Rust code that builds `Transform`, `Color`, `SetPropertyRequest` or `CallFunctionRequest` with a
  struct literal needs the new fields or `..Default::default()`.

### 6. Upgrade the package

The client package and crate are `tempo-sim` 0.4.0. A project's own package pins the `tempo-sim`
version it was generated against, so regenerate it by building, and install both together.
